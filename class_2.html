Class 2 — Transforming Text Into Numeric Vectors

Converting raw text into numbers that machine learning models can actually use

Machine learning models can't read words — they need numbers. This class covers the two main families of text vectorization: sparse vectors that count word occurrences in a vocabulary, and dense vectors (embeddings) that capture semantic meaning in compact floating-point arrays. By the end you'll be able to take any text and produce a numeric representation suitable for classification, clustering, or similarity search.

Module 1 — Sparse Vectors: Counting Words

The simplest way to represent a document numerically is to count how many times each word in the vocabulary appears. The result is a sparse vector — most entries are zero because any given document uses only a small fraction of the total vocabulary.

Why Sparse?

A vocabulary of 50,000 words means each document is represented as a vector with 50,000 dimensions. A single news article might contain only 300 unique words, so 49,700 of those dimensions will be zero. Storing all those zeros is wasteful — SciPy's sparse matrix format stores only the non-zero values and their positions.

NumPy Vectors First

Before using scikit-learn, understand what a vector is. A document vector is just a 1-D NumPy array where each position corresponds to one word in the vocabulary:

import numpy as np

# Vocabulary: ["cat", "dog", "fish", "bird"]
# Document: "I saw a cat and a dog" → cat=1, dog=1, fish=0, bird=0
doc_vec = np.array([1, 1, 0, 0])

# Multiple documents → 2D matrix (rows = docs, cols = vocab words)
dtm = np.array([
    [1, 1, 0, 0],   # doc 1: "cat dog"
    [0, 0, 1, 1],   # doc 2: "fish bird"
    [1, 0, 1, 0],   # doc 3: "cat fish"
])
print(dtm.shape)   # (3, 4)  — 3 docs, 4 vocabulary words

SciPy Sparse Matrices

For real vocabularies (thousands to millions of words), use scipy.sparse.csr_matrix (Compressed Sparse Row). It stores only the non-zero entries:

from scipy.sparse import csr_matrix
import numpy as np

dense = np.array([[1, 0, 0, 2],
                  [0, 0, 3, 0],
                  [4, 5, 0, 0]])

sparse = csr_matrix(dense)
print(sparse)
# (0, 0)  1      ← row 0, col 0, value 1
# (0, 3)  2      ← row 0, col 3, value 2
# (1, 2)  3
# (2, 0)  4
# (2, 1)  5

# Convert back to dense when needed
back = sparse.toarray()

# Convert to pandas DataFrame for display
import pandas as pd
df = pd.DataFrame(sparse.toarray(), columns=["word_a","word_b","word_c","word_d"])
CSR vs. dense: A 10,000-document corpus with a 50,000-word vocabulary would need a 10,000 × 50,000 = 500,000,000-entry dense matrix (≈ 4 GB for float64). The same data in CSR format might occupy only a few MB because most entries are zero.

Building a Document-Term Matrix with CountVectorizer

sklearn.feature_extraction.text.CountVectorizer automates the whole pipeline — tokenizing, building a vocabulary, and counting — in one step:

from sklearn.feature_extraction.text import CountVectorizer

corpus = [
    "The cat sat on the mat",
    "The dog sat on the log",
    "The cat and the dog played",
]

# Step 1: fit — learns the vocabulary from the corpus
# Step 2: transform — converts each document to a count vector
cv = CountVectorizer()
dtm = cv.fit_transform(corpus)   # returns a sparse matrix

print(type(dtm))          # <class 'scipy.sparse.csr_matrix'>
print(dtm.shape)          # (3, 8) — 3 docs × 8 unique words

# Inspect the vocabulary (word → column index)
print(cv.vocabulary_)
# {'and': 0, 'cat': 1, 'dog': 2, 'log': 3, 'mat': 4, 'on': 5, 'played': 6, 'sat': 7}
# (note: 'the' removed because max_df=1.0 by default keeps it, but it's a stopword — see below)

# Get ordered list of feature names
print(cv.get_feature_names_out())
# ['and' 'cat' 'dog' 'log' 'mat' 'on' 'played' 'sat']

Visualizing the resulting Document-Term Matrix as a table:

Key CountVectorizer Parameters

cv = CountVectorizer(
    stop_words='english',    # remove common English stopwords automatically
    lowercase=True,          # convert to lowercase (default: True)
    max_df=0.95,             # ignore words in > 95% of docs (too common)
    min_df=2,                # ignore words appearing in fewer than 2 docs (too rare)
    max_features=5000,       # keep only the top 5000 most frequent words
    ngram_range=(1, 2),      # include both unigrams and bigrams
    token_pattern=r'(?u)\b\w\w+\b',  # default: words of 2+ characters
)

# Fit separately from transform (important for train/test splits!)
cv.fit(train_docs)           # learns vocabulary from training data only
train_dtm = cv.transform(train_docs)
test_dtm  = cv.transform(test_docs)   # uses the same vocabulary!
Never fit on test data. Always call fit_transform() on training data, then only transform() on test/validation data. Fitting on test data causes data leakage — the vocabulary will include words only seen in test documents, making your model appear to generalize when it doesn't.

TF-IDF: Weighting by Importance

Raw counts have a problem: a word like "the" appears in every document and gets a high count, but it carries no useful information. TF-IDF (Term Frequency–Inverse Document Frequency) downweights common words and upweights rare, informative ones.

The formula:
TF(t, d) = count of term t in document d / total terms in d
IDF(t) = log(total documents / documents containing t)
TF-IDF(t, d) = TF(t, d) × IDF(t)

A word that appears in every document gets IDF ≈ 0 (log(N/N) = 0). A word appearing in only 1 of 1000 documents gets IDF = log(1000) ≈ 6.9.

Approach 1: TfidfVectorizer (all-in-one)

from sklearn.feature_extraction.text import TfidfVectorizer

corpus = [
    "The cat sat on the mat",
    "The dog sat on the log",
    "The cat and the dog played",
]

tfidf = TfidfVectorizer(stop_words='english')
tfidf_matrix = tfidf.fit_transform(corpus)

print(tfidf_matrix.shape)    # (3, 6) — 3 docs × 6 non-stopwords

import pandas as pd
df = pd.DataFrame(
    tfidf_matrix.toarray(),
    columns=tfidf.get_feature_names_out()
)
print(df.round(3))
#        cat    dog    log    mat  played    sat
# 0    0.582  0.000  0.000  0.582   0.000  0.416
# 1    0.000  0.582  0.582  0.000   0.000  0.416
# 2    0.408  0.408  0.000  0.000   0.580  0.000
# "played" has the highest weight in doc 3 because it's unique to that document

Approach 2: TfidfTransformer on an existing DTM

If you already have a CountVectorizer DTM, apply TF-IDF weighting separately without re-tokenizing:

from sklearn.feature_extraction.text import CountVectorizer, TfidfTransformer

cv  = CountVectorizer(stop_words='english')
dtm = cv.fit_transform(corpus)     # raw counts

tfidf_t = TfidfTransformer()
tfidf_matrix = tfidf_t.fit_transform(dtm)  # apply TF-IDF weighting

# Same result as TfidfVectorizer, but in two explicit steps

Thresholding — Finding Informative Words

A common analysis is to find the top-N most important words per document by thresholding TF-IDF scores:

import numpy as np

# Get feature names and TF-IDF array
features = tfidf.get_feature_names_out()
arr = tfidf_matrix.toarray()

# Top 3 most informative words for each document
for i, row in enumerate(arr):
    top_idx = np.argsort(row)[::-1][:3]   # indices of top 3 scores
    print(f"Doc {i+1}: {[(features[j], round(row[j],3)) for j in top_idx]}")
# Doc 1: [('cat', 0.582), ('mat', 0.582), ('sat', 0.416)]
# Doc 2: [('dog', 0.582), ('log', 0.582), ('sat', 0.416)]
# Doc 3: [('played', 0.580), ('cat', 0.408), ('dog', 0.408)]

Module 2 — Dense Embeddings: Meaning in Vectors

Dense word embeddings encode semantic relationships: words with similar meanings end up near each other in vector space. This means vector arithmetic can capture meaning — the classic example being king − man + woman ≈ queen.

How Word2Vec Works (Conceptually)

Word2Vec trains a neural network to predict a word from its context (CBOW) or predict context from a word (Skip-gram). The trained weights of the network become the word vectors. Words that appear in similar contexts end up with similar vectors — which means similar meaning.

Loading Pretrained Embeddings with Gensim

Training your own embeddings requires a large corpus. For most tasks, start with pretrained models — vectors trained on billions of words of text:

import gensim.downloader as api

# List available pretrained models
print(api.info()['models'].keys())
# dict_keys(['fasttext-wiki-news-subwords-300', 'conceptnet-numberbatch-17-06-300',
#            'word2vec-ruscorpora-300', 'word2vec-google-news-300',
#            'glove-wiki-gigaword-50', 'glove-wiki-gigaword-100',
#            'glove-wiki-gigaword-200', 'glove-wiki-gigaword-300',
#            'glove-twitter-25', 'glove-twitter-50', ...])

# Download and load (cached after first download)
model = api.load('glove-wiki-gigaword-100')   # GloVe, 100-dim vectors
print(type(model))   # <class 'gensim.models.keyedvectors.KeyedVectors'>
Which model to choose? Start with glove-wiki-gigaword-100 — it's fast to download, covers general English, and 100 dimensions is a good balance. Use word2vec-google-news-300 for higher quality at the cost of larger file size (≈1.7 GB).

Extracting Word Vectors

A KeyedVectors object is essentially a dictionary mapping words to vectors. Access vectors with square-bracket syntax:

# Get the vector for a single word
vec_cat = model['cat']
print(vec_cat.shape)    # (100,)  — 100-dimensional float vector
print(vec_cat[:5])      # [-0.301  0.127  0.652 -0.091  0.204]

# Check if a word is in the vocabulary
'cat'       in model   # True
'flurbgle'  in model   # False  — out of vocabulary (OOV)

# Get vocabulary size
print(len(model))       # 400000 words

# Inspect the vocabulary (first 10 words)
print(list(model.key_to_index.keys())[:10])

Finding Similar Words with .most_similar()

# Words closest to "king" in vector space
model.most_similar('king', topn=5)
# [('queen', 0.7699), ('prince', 0.7449), ('throne', 0.7071),
#  ('monarch', 0.6952), ('kingdom', 0.6899)]

# Cosine similarity between two specific words
model.similarity('cat', 'dog')     # 0.8016  — high similarity
model.similarity('cat', 'rocket')  # 0.1103  — low similarity

Analogy Arithmetic

Vector arithmetic captures semantic relationships. The idea: if v(king) − v(man) + v(woman), what word's vector is closest to the result?

# "king is to man as ? is to woman"
result = model.most_similar(positive=['king', 'woman'], negative=['man'], topn=3)
print(result)
# [('queen', 0.7699), ('princess', 0.7080), ('monarch', 0.6521)]

# "Paris is to France as Berlin is to ?"
result = model.most_similar(positive=['berlin', 'france'], negative=['paris'], topn=1)
print(result)
# [('germany', 0.9219)]

Long-Tail Vocabulary Problem

Word frequency follows a power law: a small number of words appear extremely often, while the vast majority appear rarely. Rare words in your corpus may not appear in the pretrained model's vocabulary at all.

from collections import Counter
import matplotlib.pyplot as plt

words = text.lower().split()
freq = Counter(words)

# Roughly: 50% of unique words appear only once ("hapax legomena")
hapax = sum(1 for w, c in freq.items() if c == 1)
print(f"{hapax}/{len(freq)} words appear exactly once = {hapax/len(freq):.1%}")
Preprocessing helps. Lemmatizing collapses "run", "runs", "running", "ran" into "run" — reducing rare forms that individually had low frequency but together are common.

Building Sentence Vectors by Averaging

Word2Vec/GloVe produce word vectors. To represent a whole sentence or document, average the vectors of its words:

import numpy as np

def sentence_vector(sentence, model, dim=100):
    """Average word vectors, skipping OOV words."""
    words = sentence.lower().split()
    vecs  = [model[w] for w in words if w in model]
    if not vecs:
        return np.zeros(dim)
    return np.mean(vecs, axis=0)

doc1_vec = sentence_vector("the cat sat on the mat", model)
doc2_vec = sentence_vector("a dog ran in the park", model)
print(doc1_vec.shape)   # (100,)
Averaging loses word order. "The dog bit the man" and "The man bit the dog" produce the same averaged vector — the order information is lost. For tasks where word order matters (sentiment, question answering), use transformer models (BERT, Sentence-BERT) instead.

Visualizing Word Vectors with PCA

100+ dimensional vectors can't be plotted directly. PCA (Principal Component Analysis) compresses them to 2D while preserving as much variation as possible:

from sklearn.decomposition import PCA
import matplotlib.pyplot as plt

words = ['king', 'queen', 'man', 'woman', 'dog', 'cat', 'Paris', 'France', 'Berlin', 'Germany']
vectors = np.array([model[w.lower()] for w in words if w.lower() in model])

pca = PCA(n_components=2)
coords = pca.fit_transform(vectors)

plt.figure(figsize=(8, 6))
for i, word in enumerate(words):
    if word.lower() in model:
        plt.scatter(coords[i, 0], coords[i, 1])
        plt.annotate(word, (coords[i, 0], coords[i, 1]), fontsize=11)
plt.title("Word Vectors — PCA to 2D")
plt.tight_layout()
plt.show()

FastText — Handling Out-of-Vocabulary Words

Word2Vec and GloVe produce a fixed vocabulary. If a word wasn't in training data, there's no vector for it. FastText solves this by decomposing each word into character n-grams and training vectors for those. The word vector is the sum of its n-gram vectors, so it can estimate a vector for any word, even ones it never saw during training.

import gensim.downloader as api

# FastText trained on Wikipedia + news
ft_model = api.load('fasttext-wiki-news-subwords-300')

# Regular Word2Vec would fail on "unhappiness" if not in vocab
# FastText computes: un + happy + ness + ... = estimated vector
vec = ft_model['unfathomable']   # works even if rare/OOV
print(vec.shape)   # (300,)

# Character n-grams: "playing" → ["pla", "lay", "ayi", "yin", "ing", "playing"]
# Each n-gram has a vector; their sum ≈ the word vector
When to use FastText: When your corpus contains domain-specific jargon, brand names, misspellings, or other rare words not found in general vocabulary models. FastText is especially useful for social media text, medical notes, or code-switching text.

Module 3 — Measuring Similarity Between Vectors

Once you have vectors, you need to measure how close two vectors are — to find similar documents, rank search results, or cluster related items. Three metrics are used throughout NLP:

Dot Product

The dot product (inner product) multiplies corresponding elements and sums the results. It measures both direction and magnitude:

import numpy as np

a = np.array([1, 2, 3])
b = np.array([4, 5, 6])

dot = np.dot(a, b)          # 1*4 + 2*5 + 3*6 = 32
dot_alt = (a * b).sum()     # same thing, element-wise then sum

Cosine Similarity

Cosine similarity normalizes by vector length, so it measures the angle between vectors regardless of their magnitude. This is the most commonly used metric for text because document length shouldn't affect similarity:

def cosine_similarity(a, b):
    return np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b))

# Range: −1 (opposite) to 1 (identical direction)
cosine_similarity(model['cat'], model['dog'])     # ≈ 0.80  — similar
cosine_similarity(model['cat'], model['rocket'])  # ≈ 0.11  — dissimilar

# Using scikit-learn (handles matrices efficiently)
from sklearn.metrics.pairwise import cosine_similarity as sk_cosine
vecs = np.array([model['cat'], model['dog'], model['fish']])
sim_matrix = sk_cosine(vecs)
print(sim_matrix.round(3))
# [[1.000  0.802  0.651]
#  [0.802  1.000  0.603]
#  [0.651  0.603  1.000]]

Euclidean Distance

Euclidean distance is the straight-line distance between two points in vector space. Unlike cosine, it is sensitive to vector magnitude:

from scipy.spatial.distance import euclidean

dist = euclidean(model['cat'], model['dog'])
print(dist)   # smaller = more similar (opposite of cosine similarity)

# Or with numpy
dist_np = np.linalg.norm(model['cat'] - model['dog'])

Building a Pairwise Document Similarity Matrix

To find all pairwise similarities in a corpus — useful for clustering or nearest-neighbor search:

from sklearn.metrics.pairwise import cosine_similarity
import pandas as pd

corpus = [
    "The cat sat on the mat",
    "The dog sat on the log",
    "The cat and the dog played",
    "The fish swam in the sea",
]

tfidf = TfidfVectorizer(stop_words='english')
tfidf_matrix = tfidf.fit_transform(corpus)

# Pairwise similarity: shape = (n_docs, n_docs)
sim_matrix = cosine_similarity(tfidf_matrix)

df_sim = pd.DataFrame(sim_matrix.round(3),
                      index=[f"doc{i+1}" for i in range(len(corpus))],
                      columns=[f"doc{i+1}" for i in range(len(corpus))])
print(df_sim)
#        doc1   doc2   doc3   doc4
# doc1  1.000  0.463  0.270  0.000
# doc2  0.463  1.000  0.270  0.000
# doc3  0.270  0.270  1.000  0.000
# doc4  0.000  0.000  0.000  1.000
# doc4 (fish/sea) shares no vocabulary with the cat/dog documents

Document Search: Query vs. Corpus

To search a corpus with a query string, transform the query using the already-fitted vectorizer (never re-fit on the query):

query = "cat playing on mat"
query_vec = tfidf.transform([query])       # transform only — same vocabulary!

scores = cosine_similarity(query_vec, tfidf_matrix)   # shape: (1, n_docs)
ranked = np.argsort(scores[0])[::-1]       # sort by score, descending

for rank, idx in enumerate(ranked):
    print(f"Rank {rank+1}: doc{idx+1} — score={scores[0][idx]:.3f}")
Always use transform(), not fit_transform() on queries. If you re-fit on the query, the vectorizer learns a new vocabulary with only query words, and the resulting vector has a completely different structure than the corpus vectors.
