Module 1 — Finding Simple Patterns in Text

This module starts with the simplest possible tools: Python's built-in string methods. The goal is to extract tokens (individual words or units) from raw text and count them to discover what words appear most often.

Basic String Operations

Two operations you will use constantly in NLP:

  • str.lower() — converts all characters to lowercase so "The" and "the" are treated as the same word
  • str.split() — splits a string on whitespace, producing a list of tokens
text = "The quick brown Fox jumps over the lazy Dog"
tokens = text.lower().split()
# ['the', 'quick', 'brown', 'fox', 'jumps', 'over', 'the', 'lazy', 'dog']

Regex Pattern Matching with re

Regular expressions let you define flexible patterns to find or replace text. Python's re module is the standard tool for this.

import re

# Find all sequences of word characters (letters/digits)
tokens = re.findall(r'\b[a-z]+\b', text.lower())

# Remove punctuation
clean = re.sub(r'[^a-z\s]', '', text.lower())
Why regex? split() leaves punctuation attached to words ("dog." instead of "dog"). Regex lets you define exactly what counts as a token.

Counting Tokens with Counter

collections.Counter is a dictionary subclass that counts how many times each element appears in an iterable. It is the fastest built-in way to build a word-frequency table.

from collections import Counter

tokens = ['the', 'cat', 'sat', 'on', 'the', 'mat', 'the']
counts = Counter(tokens)
print(counts.most_common(3))
# [('the', 3), ('cat', 1), ('sat', 1)]
  • Counter(iterable) — builds the frequency dictionary in one step
  • .most_common(n) — returns the top n items as (word, count) tuples, sorted by frequency

Introducing NLTK

The Natural Language Toolkit (nltk) is the most widely used Python library for NLP preprocessing. Before using its data (corpora, tokenizers, stopword lists), you must download the required packages once:

import nltk

nltk.download('wordnet')       # WordNet lexical database
nltk.download('brown')         # Brown corpus (for practice)
nltk.download('averaged_perceptron_tagger')  # POS tagger

You can then load a large text corpus for experiments:

# All unique lowercased words from the Brown corpus
Ss6 = {s.lower() for s in nltk.corpus.brown.words()}

Unicode Normalization

Text from the web often contains accented characters (é, ü, ñ) or special Unicode symbols. Normalizing to ASCII removes these so tokens are consistent:

import unicodedata

def normalize(word):
    return unicodedata.normalize('NFKD', word).encode('ascii', 'ignore').decode('utf-8')

normalize('café')   # → 'cafe'
normalize('naïve')  # → 'naive'
What is NFKD? Unicode Normalization Form KD decomposes characters into their base letter plus a combining accent mark. The encode('ascii', 'ignore') then drops the accent, leaving only the base letter.

Expanding Contractions

Contractions like "don't" or "I'm" are actually two words combined. Expanding them before tokenizing prevents "don't" and "do not" from being treated as different terms.

# Simple approach — a lookup dictionary + regex substitution
CONTRACTIONS = {"don't": "do not", "I'm": "I am", "it's": "it is", ...}

# Or use the contractions library (handles hundreds of cases automatically)
import contractions
contractions.fix("I don't know what it's about.")
# → "I do not know what it is about."

Tokenization

Tokenization is the process of splitting a string into a list of tokens (words, sentences, or subwords). NLTK provides two key tokenizers:

import nltk

sDoc = "I love NLP. It's fascinating!"

# Split into sentences
LsSents = nltk.sent_tokenize(sDoc)
# → ["I love NLP.", "It's fascinating!"]

# Split into words (handles punctuation correctly)
LsWords = nltk.word_tokenize(sDoc)
# → ['I', 'love', 'NLP', '.', 'It', "'s", 'fascinating', '!']
Punkt Tokenizer: NLTK's sentence tokenizer uses the Punkt algorithm — an unsupervised model trained on large corpora to recognize sentence boundaries. It handles abbreviations ("Dr.", "U.S.A.") without splitting on every period.

Removing Stopwords

Stopwords are extremely common words ("the", "a", "is", "and") that carry little meaning on their own and inflate vocabulary size. Removing them reduces noise:

from nltk.corpus import stopwords

stop_words = set(stopwords.words('english'))
filtered = [w for w in tokens if w.lower() not in stop_words]

Stemming

Stemming removes suffixes from words to reduce them to a common root (the stem). The stem does not need to be a real dictionary word — it just needs to group similar words together.

from nltk.stem import PorterStemmer

ps = PorterStemmer()
ps.stem('running')   # → 'run'
ps.stem('studies')   # → 'studi'   (not a real word — that's OK)
ps.stem('fairly')    # → 'fairli'
Stemming is fast but crude. It uses fixed rules (chop off "-ing", "-ed", "-s") without any knowledge of the word's meaning. Use it when speed matters more than accuracy.

Lemmatization

Lemmatization also reduces words to a base form (the lemma), but it uses a real dictionary (WordNet) and the word's grammatical role. The result is always a valid English word.

from nltk.stem import WordNetLemmatizer

lem = WordNetLemmatizer()
lem.lemmatize('running', pos='v')   # → 'run'   (verb)
lem.lemmatize('better',  pos='a')   # → 'good'  (adjective — knows "better" is comparative of "good")
lem.lemmatize('studies', pos='v')   # → 'study' (not "studi" like Porter)

The Pipe Class — A Reusable Pipeline

Rather than applying each step manually every time, the course introduces a custom Pipe class that chains preprocessing operations together using Python @property decorators. Each property modifies the token list in-place and returns self, enabling method chaining.

# How you call the pipeline — each step is a property, no parentheses needed
pp = Pipe(LsBookWords, SsStopWords='nltk', SsLex='nltk').Low.Norm.Exp.Words.Stem.Stop.NoNum

# The steps in order:
#   .Low    → lowercase all tokens
#   .Norm   → normalize unicode to ASCII
#   .Exp    → expand contractions
#   .Words  → keep only alphabetic tokens
#   .Stem   → apply Porter stemmer
#   .Stop   → remove stopwords
#   .NoNum  → remove numeric tokens
How @property enables chaining: Each method is decorated with @property, which means you access it as an attribute (no parentheses). Each method transforms self.LsWords and returns self, so the next step is called on the same object. This makes the pipeline read like a sentence.

The pipeline also records statistics at each step (original token count vs. count after each operation), so you can see exactly how much each step reduces the vocabulary.

The enumerate() Function

Used throughout preprocessing to loop over a list while keeping track of position:

sentences = ['Hello world.', 'NLP is fun.', 'Let us begin.']
for i, sent in enumerate(sentences):
    print(i, sent)
# 0 Hello world.
# 1 NLP is fun.
# 2 Let us begin.

Module 3 — Tagging and Parsing a Document

Once text is tokenized, we can assign a part-of-speech (POS) tag to each word. Tags tell the computer whether a word is a noun, verb, adjective, etc. — which is essential for accurate lemmatization and phrase extraction.

Part-of-Speech Tagging

import nltk

tokens = nltk.word_tokenize("The cat sat on the mat.")
tagged = nltk.pos_tag(tokens)
# [('The','DT'), ('cat','NN'), ('sat','VBD'), ('on','IN'), ('the','DT'), ('mat','NN'), ('.', '.')]

Converting Penn Tags to WordNet Tags

There is a mismatch: nltk.pos_tag() produces Penn Treebank tags, but WordNetLemmatizer expects WordNet tags ('n', 'v', 'a', 'r'). You must convert between them before lemmatizing:

from nltk.corpus import wordnet

def penn_to_wordnet(tag):
    if tag.startswith('J'):
        return wordnet.ADJ      # 'a'
    elif tag.startswith('V'):
        return wordnet.VERB     # 'v'
    elif tag.startswith('N'):
        return wordnet.NOUN     # 'n'
    elif tag.startswith('R'):
        return wordnet.ADV      # 'r'
    else:
        return wordnet.NOUN     # default to noun

# Lemmatize each word using its POS tag
from nltk.stem import WordNetLemmatizer
lem = WordNetLemmatizer()

tagged = [('running', 'VBG'), ('cats', 'NNS'), ('better', 'JJR')]
lemmatized = [lem.lemmatize(word, penn_to_wordnet(tag)) for word, tag in tagged]
# → ['run', 'cat', 'good']
Why does this matter? Without providing a POS tag, WordNetLemmatizer defaults to treating every word as a noun. That means "running" → "running" (unchanged) instead of "run". Providing the correct tag dramatically improves lemmatization quality.

Chunking — Extracting Phrases

Chunking (also called shallow parsing) groups consecutive tagged tokens into meaningful phrases like noun phrases (NP) or verb phrases (VP). You define grammar rules as regex patterns over POS tags, and NLTK's RegexpParser applies them.

# Grammar rule: an optional determiner, optional adjective, followed by one or more nouns
sGrammar = r'NP: {
? ? +}'
parser = nltk.RegexpParser(sGrammar)

tagged = nltk.pos_tag(nltk.word_tokenize("The big brown dog sat quietly."))
ChunkTree = parser.parse(tagged)
print(ChunkTree)
# (S
#   (NP The/DT big/JJ dog/NN)     ← chunk found
#   sat/VBD
#   quietly/RB ./.)

Common grammar patterns:

PatternCapturesExample match
NP: {<DT>? <JJ>? <NN.*>+}Noun phrases"the big dog", "cats"
VP: {<V.*>+}Verb phrases"has been running"
NP1: {<DT>? <JJ>? <NN.*>+}Simpler noun phrases"quick fox"
Chunking vs. full parsing: Chunking finds flat phrases (no nesting or hierarchy) and is fast. Full syntactic parsing builds a complete tree of a sentence's grammatical structure but is much slower. For most NLP tasks, chunking is sufficient.

Parse Trees

NLTK can also produce three types of parse trees for deeper structural analysis:

  • Constituency parse — breaks the sentence into nested phrases (NP, VP, etc.) according to grammar rules
  • Dependency parse — draws directed edges between words showing which word depends on which (e.g., "dog" is the subject of "sat")
  • Syntactic parse — a full hierarchical tree of the sentence structure

For production-quality parsing, the spaCy library is far faster and more accurate than NLTK's built-in parsers.
