Class 5 — Clustering Documents With Unsupervised Machine Learning

Grouping similar texts without labels — from string metrics to semantic embeddings

Clustering finds natural groupings in data without any pre-defined categories. Where classification (Class 3) requires thousands of labeled examples, clustering only needs the documents themselves. This class builds from simple string-level similarity metrics all the way to clustering dense sentence embeddings, and covers how to evaluate whether the resulting clusters are actually meaningful.

Module 1 — Similarity and Distance Metrics

Before clustering documents, you need a way to measure how similar two documents are. The right metric depends on whether you're comparing sets of words, character sequences, or dense embedding vectors.

Jaccard Similarity — Set Overlap

Jaccard similarity treats each document as a set of words and measures the fraction of vocabulary shared between two documents. It ignores word order and counts only presence or absence:

def jaccard_similarity(doc_a, doc_b):
    set_a = set(doc_a.lower().split())
    set_b = set(doc_b.lower().split())
    intersection = set_a & set_b
    union        = set_a | set_b
    return len(intersection) / len(union) if union else 0.0

a = "the cat sat on the mat"
b = "the cat and the dog played"
c = "the rocket launched into orbit"

print(jaccard_similarity(a, b))   # 0.375 — share "the", "cat"
print(jaccard_similarity(a, c))   # 0.083 — share only "the"

# Range: 0.0 (no overlap) to 1.0 (identical sets)
Jaccard distance = 1 − Jaccard similarity. Use Jaccard similarity when you care about shared vocabulary; use Jaccard distance when you need a proper distance metric for clustering algorithms that expect dissimilarity.

Hamming Distance — Position-by-Position Differences

Hamming distance counts the number of positions where two equal-length sequences differ. It was originally designed for binary strings but applies to any fixed-length sequence:

def hamming_distance(s1, s2):
    if len(s1) != len(s2):
        raise ValueError("Hamming distance requires equal-length strings")
    return sum(c1 != c2 for c1, c2 in zip(s1, s2))

hamming_distance("karolin", "kathrin")   # 3 — positions 2, 4, 5 differ
hamming_distance("1011101", "1001001")   # 2

# Use cases: error detection in bit strings, comparing fixed-length codes, DNA sequences
Hamming requires equal length. For strings of different lengths, use Levenshtein edit distance instead — it handles insertions and deletions.

Levenshtein (Edit) Distance — Flexible String Comparison

Edit distance counts the minimum number of insertions, deletions, and substitutions needed to transform one string into another. It works on strings of any length and is the standard metric for spell-checking and fuzzy matching:

from Levenshtein import distance   # pip install python-Levenshtein

distance("kitten", "sitting")   # 3
# k→s (substitution), e→i (substitution), insert g at end

distance("saturday", "sunday")  # 3
distance("",         "hello")   # 5 (5 insertions)
distance("hello",    "hello")   # 0 (identical)

# Normalized edit distance: divide by max possible distance
def normalized_levenshtein(s1, s2):
    max_len = max(len(s1), len(s2))
    if max_len == 0:
        return 0.0
    return distance(s1, s2) / max_len

normalized_levenshtein("kitten", "sitting")   # 3/7 ≈ 0.43

Finding Mismatches in Record Linkage

Edit distance is widely used to find near-duplicate records — for example, matching customer names across databases where one has typos or abbreviations:

import pandas as pd
from Levenshtein import distance

names_a = ["John Smith", "Jane Doe", "Robert Johnson", "Mary Williams"]
names_b = ["Jon Smith",  "Jane Doe", "Rob Johnson",    "Maria Williams"]

threshold = 3   # strings within 3 edits are likely the same entity

for a, b in zip(names_a, names_b):
    d = distance(a, b)
    match = "MATCH" if d <= threshold else "no match"
    print(f"{d:2d}  {match}  |  '{a}'  vs  '{b}'")

Sentence Embeddings with SBERT

String metrics work on surface form. For semantic similarity — where "automobile" and "car" should be close even though they share no characters — you need dense embedding vectors. Sentence-BERT (SBERT) produces 384- or 768-dimensional vectors where semantic similarity corresponds to vector proximity:

from sentence_transformers import SentenceTransformer
import numpy as np

model = SentenceTransformer('all-MiniLM-L6-v2')   # fast, 384-dim

sentences = [
    "The cat sat on the mat.",
    "A feline rested on the rug.",   # same meaning, different words
    "The dog chased the ball.",
    "A rocket launched into orbit.",
]

# Encode all sentences at once (batched internally)
embeddings = model.encode(sentences)
print(embeddings.shape)   # (4, 384)

# Cosine similarity between sentence 0 and sentence 1
from sklearn.metrics.pairwise import cosine_similarity
sim = cosine_similarity(embeddings[0:1], embeddings[1:2])[0][0]
print(f"cat/mat vs feline/rug: {sim:.3f}")   # ≈ 0.85 — high semantic similarity
Why SBERT over word averaging? Averaging Word2Vec/GloVe vectors loses sentence structure and negation. SBERT fine-tunes BERT with a siamese network on sentence-pair tasks, so the resulting vectors are specifically optimized for semantic sentence similarity.

Agglomerative Clustering with scikit-learn

Agglomerative clustering starts with every document in its own cluster and repeatedly merges the two closest clusters until only one remains:

from sklearn.cluster import AgglomerativeClustering
from sentence_transformers import SentenceTransformer

model_sbert = SentenceTransformer('all-MiniLM-L6-v2')
embeddings  = model_sbert.encode(documents)

# Cluster into 5 groups using cosine distance and average linkage
agg = AgglomerativeClustering(
    n_clusters=5,
    metric='cosine',
    linkage='average',
)
labels = agg.fit_predict(embeddings)
print(labels)   # [0, 2, 0, 1, 3, 2, 0, 4, ...]  — cluster assignment per document

# Group documents by cluster
from collections import defaultdict
clusters = defaultdict(list)
for doc, label in zip(documents, labels):
    clusters[label].append(doc)

for cluster_id, docs in sorted(clusters.items()):
    print(f"\n--- Cluster {cluster_id} ({len(docs)} docs) ---")
    for d in docs[:3]:
        print(" ", d[:80])

Linkage Methods

The linkage method determines how distance between two clusters is measured when deciding which to merge next:

LinkageDistance between clusters A and B is…Produces
singleDistance between the two closest points (one from each cluster)Long, chain-like clusters ("chaining effect")
completeDistance between the two farthest pointsCompact, roughly spherical clusters
averageAverage of all pairwise distances between the clustersGood balance — most common choice for text
wardIncrease in total within-cluster variance from mergingMinimizes intra-cluster variance; requires Euclidean distance

Dendrograms with SciPy

A dendrogram visualizes the full merge history. The y-axis shows the distance at which each merge happened — clusters merged at a high distance are dissimilar:

from scipy.cluster.hierarchy import dendrogram, linkage, fcluster
import matplotlib.pyplot as plt
import numpy as np
from sklearn.metrics.pairwise import cosine_distances

# SciPy linkage works on a distance matrix (not similarity)
dist_matrix = cosine_distances(embeddings)

# Condense to upper-triangle vector (required by SciPy)
from scipy.spatial.distance import squareform
condensed = squareform(dist_matrix)

# Compute linkage matrix
Z = linkage(condensed, method='average')   # Z shape: (n-1, 4)

# Plot dendrogram
plt.figure(figsize=(12, 5))
dendrogram(
    Z,
    labels=[doc[:30] for doc in documents],
    leaf_rotation=90,
    leaf_font_size=8,
)
plt.title("Hierarchical Clustering Dendrogram")
plt.tight_layout()
plt.show()

# Cut the tree to get flat cluster labels
labels = fcluster(Z, t=0.4, criterion='distance')   # cut at distance 0.4
# or
labels = fcluster(Z, t=5, criterion='maxclust')      # exactly 5 clusters
Reading a dendrogram: The horizontal line where you "cut" the tree determines the number of clusters — each vertical branch below the cut becomes one cluster. A good cut leaves a large vertical gap between merges, meaning the clusters you're keeping are well-separated.

Module 3 — K-Means Clustering and Evaluation

K-means partitions documents into exactly k clusters by alternating between assigning each document to its nearest cluster center (centroid) and recomputing centroids from the assigned documents. It's fast and scales well, but requires choosing k in advance.

K-Means on Sentence Embeddings

from sklearn.cluster import KMeans
from sentence_transformers import SentenceTransformer

sbert  = SentenceTransformer('all-MiniLM-L6-v2')
embeds = sbert.encode(documents)

km = KMeans(
    n_clusters=5,
    n_init=10,          # run 10 times with different random seeds, keep best
    max_iter=300,
    random_state=42,
)
km.fit(embeds)

labels    = km.labels_          # cluster index for each document
centroids = km.cluster_centers_ # shape: (k, embedding_dim)
inertia   = km.inertia_         # sum of squared distances to nearest centroid

print(f"Inertia: {inertia:.2f}")   # lower = tighter clusters
K-means uses Euclidean distance. Sentence embeddings are typically L2-normalized, so Euclidean distance and cosine distance give the same ranking. If your embeddings are not normalized, normalize them first: embeds = embeds / np.linalg.norm(embeds, axis=1, keepdims=True)

Centroids vs. Medoids

The centroid of a cluster is the mean of all its member vectors — a mathematical average that may not correspond to any actual document. The medoid is the actual document whose vector is closest to the centroid — useful when you need a real representative example:

import numpy as np
from sklearn.metrics.pairwise import cosine_distances

def find_medoids(embeddings, labels, k):
    """For each cluster, find the document index closest to the centroid."""
    medoid_indices = []
    for cluster_id in range(k):
        mask    = labels == cluster_id
        cluster_embeds = embeddings[mask]
        cluster_indices = np.where(mask)[0]
        # Compute centroid
        centroid = cluster_embeds.mean(axis=0, keepdims=True)
        # Find closest actual document to the centroid
        dists = cosine_distances(centroid, cluster_embeds)[0]
        medoid_local = dists.argmin()
        medoid_indices.append(cluster_indices[medoid_local])
    return medoid_indices

medoids = find_medoids(embeds, km.labels_, k=5)
for cluster_id, idx in enumerate(medoids):
    print(f"Cluster {cluster_id} representative: {documents[idx][:80]}")

Choosing k — The Elbow Method

Plot inertia (sum of squared distances to centroids) against k. Inertia always decreases as k increases, but the rate of decrease slows — the "elbow" is where adding more clusters gives diminishing returns:

import matplotlib.pyplot as plt

inertias = []
k_range  = range(2, 20)

for k in k_range:
    km_k = KMeans(n_clusters=k, n_init=10, random_state=42)
    km_k.fit(embeds)
    inertias.append(km_k.inertia_)

plt.plot(k_range, inertias, marker='o')
plt.xlabel("Number of clusters k")
plt.ylabel("Inertia (sum of squared distances)")
plt.title("Elbow Method for Selecting k")
plt.show()

Silhouette Score — How Well-Separated Are the Clusters?

The silhouette score for a single document measures how much closer it is to its own cluster than to the nearest other cluster:

from sklearn.metrics import silhouette_score, silhouette_samples
import matplotlib.pyplot as plt
import numpy as np

# Overall score: mean silhouette across all documents
score = silhouette_score(embeds, km.labels_, metric='cosine')
print(f"Silhouette score: {score:.4f}")
# Range: -1 (wrong cluster) to 0 (on boundary) to +1 (tight cluster, well separated)
# Typical good clustering: > 0.3; excellent: > 0.5

# Per-sample scores — useful for finding outliers in each cluster
sample_scores = silhouette_samples(embeds, km.labels_, metric='cosine')

# Plot silhouette per cluster
fig, ax = plt.subplots(figsize=(8, 5))
y_lower = 0
for cluster_id in range(km.n_clusters):
    cluster_scores = sorted(sample_scores[km.labels_ == cluster_id])
    size = len(cluster_scores)
    ax.barh(range(y_lower, y_lower + size), cluster_scores, height=1.0)
    y_lower += size + 5
ax.axvline(score, color='red', linestyle='--', label=f'Mean = {score:.3f}')
ax.set_xlabel("Silhouette score"); ax.legend()
plt.tight_layout(); plt.show()

Adjusted Rand Index — Comparing to Ground Truth

If you have ground-truth labels (e.g., known genre labels for movie descriptions), the Adjusted Rand Index (ARI) measures how well your clustering matches them. ARI = 1.0 is a perfect match; ARI = 0 is random:

from sklearn.metrics import adjusted_rand_score

# true_labels: ground truth (e.g., genre ids)
# pred_labels: cluster assignments from KMeans

ari = adjusted_rand_score(true_labels, pred_labels)
print(f"ARI: {ari:.4f}")
# ARI = 1.0 → perfect match with ground truth
# ARI = 0.0 → no better than random assignment
# ARI can be negative if clustering is worse than random

# Try different k values and compare ARI
for k in range(3, 12):
    km_k   = KMeans(n_clusters=k, n_init=10, random_state=42).fit(embeds)
    sil    = silhouette_score(embeds, km_k.labels_, metric='cosine')
    ari_k  = adjusted_rand_score(true_labels, km_k.labels_)
    print(f"k={k:2d}  silhouette={sil:.3f}  ARI={ari_k:.3f}")
Silhouette vs. ARI: Silhouette score is unsupervised — it only uses the vectors, not any labels, so you can always compute it. ARI requires ground-truth labels, but it's a much more direct measure of whether your clusters match the real categories. Use silhouette when you have no labels; use ARI to validate when you do.

Putting It All Together — Movie Description Clustering

import pandas as pd
from sentence_transformers import SentenceTransformer
from sklearn.cluster import KMeans
from sklearn.metrics import silhouette_score, adjusted_rand_score

# Load movie descriptions (title, description, genre)
df = pd.read_csv('movies.csv')

# Encode descriptions
sbert  = SentenceTransformer('all-MiniLM-L6-v2')
embeds = sbert.encode(df['description'].tolist(), show_progress_bar=True)

# Grid search over k
results = []
for k in range(3, 15):
    km  = KMeans(n_clusters=k, n_init=10, random_state=42).fit(embeds)
    sil = silhouette_score(embeds, km.labels_, metric='cosine')
    ari = adjusted_rand_score(df['genre'], km.labels_)
    results.append({'k': k, 'silhouette': sil, 'ARI': ari})

results_df = pd.DataFrame(results)
print(results_df.to_string(index=False))

# Best k by silhouette
best_k = results_df.loc[results_df['silhouette'].idxmax(), 'k']
print(f"\nBest k by silhouette: {best_k}")
