Class 2 — Estimating Probability Distributions

From data to probabilities: the Bayes optimal classifier, MLE, smoothing, and Naive Bayes

If we knew the true probability distribution behind our data, classification would be easy: just pick the most probable label. We never know it, but we can estimate it from data. This class covers how to estimate distributions with Maximum Likelihood Estimation (MLE), why that breaks down in high dimensions, and how the Naive Bayes assumption gets around the problem. The project builds a classifier that predicts whether a baby name belongs to a boy or a girl.

Module 1 — Estimate Distributions from Data

This module starts with the Bayes optimal classifier, the best possible way to predict labels when the data's distribution is known. In practice the distribution is almost never known, so the module then shows how to estimate it from data. The worked example estimates the probability of a coin flip from sample flips, using Maximum Likelihood Estimation (MLE). These ideas set up the later modules, which deal with estimating distributions in high dimensions.

The Bayes Optimal Classifier

Assume the data is drawn from some distribution P(X, Y). If we knew P(Y | X) exactly, the best possible prediction for an input x is the label with the highest conditional probability:

h_opt(x) = argmax_y P(y | x)
Why it matters: no classifier can beat the Bayes optimal classifier. Its error rate, 1 − P(h_opt(x) | x), is the lowest error achievable on that data (the Bayes error). It is a theoretical benchmark. In practice we don't know P, so we estimate it from data.

Example: if 80% of emails containing the word "lottery" are spam, the Bayes optimal classifier labels every "lottery" email as spam and is still wrong 20% of the time. That 20% is error no model can remove.

Maximum Likelihood Estimation (MLE)

MLE picks the parameters θ that make the observed data most probable:

θ_MLE = argmax_θ P(D; θ)

Coin-flip example (binomial distribution). We flip a coin n times and see nH heads and nT tails. With θ = P(heads):

P(D; θ) = C(n, n_H) · θ^n_H · (1 − θ)^n_T

# Take the log (same argmax, easier math):
log P(D; θ) = log C(n, n_H) + n_H log θ + n_T log(1 − θ)

# Set the derivative to zero:
n_H / θ − n_T / (1 − θ) = 0
⇒  θ_MLE = n_H / (n_H + n_T)
Intuition: the MLE is just the observed fraction. Count how often something happened and divide by the number of trials.

Smoothing for Small Data Sets

MLE is unreliable when data is scarce. Flip a coin twice, get two heads, and MLE says P(tails) = 0. A zero probability is especially harmful in a classifier because it wipes out the whole product of probabilities.

Additive (Laplace) smoothing adds m imaginary observations of each outcome:

θ = (n_H + m) / (n_H + n_T + 2m)
  • m = 0 → plain MLE
  • m = 1 → classic "add-one" Laplace smoothing
  • As n → ∞, the imaginary counts stop mattering and the estimate converges to the MLE
Bayesian view: smoothing is equivalent to the MAP (maximum a posteriori) estimate with a Beta prior on θ. The m fake counts encode a prior belief that the coin is roughly fair.
import numpy as np

flips = np.array([1, 1])          # two heads
n_h, n = flips.sum(), len(flips)

for m in [0, 1, 5]:
    theta = (n_h + m) / (n + 2 * m)
    print(f"m={m}: P(heads) = {theta:.3f}")
# m=0: P(heads) = 1.000
# m=1: P(heads) = 0.750
# m=5: P(heads) = 0.583

Module 2 — Classification with the Naive Bayes Algorithm

The Curse of Dimensionality in MLE

To estimate P(y | x) directly with MLE, we count how often each exact x appears with each label:

P(y | x) ≈ count(x, y) / count(x)

This works with one or two features. But with d binary features there are 2d possible inputs. With d = 30 that's over a billion combinations. Most will never appear in the training data, so count(x) = 0 and the estimate is undefined.

Takeaway: the data needed to cover every combination grows exponentially with d. Direct MLE of P(y | x) is hopeless for realistic feature counts.

The Naive Bayes Assumption

First flip the problem with Bayes' rule, so we model P(x | y) and P(y) instead:

P(y | x) = P(x | y) P(y) / P(x)

P(y) is easy to estimate. P(x | y) is still high-dimensional. Naive Bayes makes it tractable by assuming the features are conditionally independent given the label:

P(x | y) = Π_α P(x_α | y)

Now we estimate d one-dimensional distributions per class instead of one d-dimensional distribution. Each needs only a modest amount of data.

When does it hold? Rarely exactly. In spam filtering, "free" and "money" are clearly correlated. Naive Bayes still often classifies well, because it only needs the argmax to be right, not the probabilities themselves.

The Naive Bayes Classifier

Since P(x) is the same for every label, drop it:

h(x) = argmax_y  P(y) · Π_α P(x_α | y)

# In practice use logs to avoid numerical underflow:
h(x) = argmax_y  [ log P(y) + Σ_α log P(x_α | y) ]

Categorical Naive Bayes

When each feature takes one of a fixed set of values (e.g. a letter, a color, yes/no), estimate each conditional by counting, with smoothing:

P(y = c)             = count(y = c) / n
P(x_α = j | y = c)   = (count(x_α = j, y = c) + l) / (count(y = c) + l · K_α)

# K_α = number of possible values of feature α
# l   = smoothing constant (l = 1 is Laplace smoothing)

Step 1 — Class Prior Probability

The fraction of training examples with each label, smoothed:

import numpy as np

def naivebayesPY(X, Y):
    # Add one fake boy and one fake girl (smoothing)
    Y = np.concatenate([Y, [-1, 1]])
    pos = np.mean(Y == 1)
    neg = np.mean(Y == -1)
    return pos, neg

Step 2 — Conditional Probability

For each feature, estimate P(xα | y) separately for boys and girls. With count (multinomial) features, use the share of total feature mass for that class, smoothed by adding 1 to every count:

def naivebayesPXY(X, Y):
    n, d = X.shape
    # Smoothing: one fake example per class with all features on
    X = np.concatenate([X, np.ones((2, d))])
    Y = np.concatenate([Y, [-1, 1]])

    posprob = X[Y == 1].sum(axis=0) / X[Y == 1].sum()
    negprob = X[Y == -1].sum(axis=0) / X[Y == -1].sum()
    return posprob, negprob

Step 3 — Feature Vectors via Hashing

Names have different lengths, so convert each one to a fixed-size vector. The hashing trick maps every feature string (a letter, a prefix, a suffix) to one of d buckets:

def hashfeatures(name, d=128, prefix_len=3, suffix_len=3):
    v = np.zeros(d)
    name = name.lower()
    feats = [name[:prefix_len] + ">", "<" + name[-suffix_len:]]
    feats += list(name)                       # individual letters
    for f in feats:
        v[hash(f) % d] += 1
    return v

hashfeatures("Emma")   # array of length 128 with a few nonzero counts
Improving features: suffixes carry a lot of signal ("‑a" leans girl, "‑o" leans boy). Adding prefix/suffix features of different lengths usually helps more than tuning the model.

Step 4 — Classify

Compute the log-odds. If it's positive, predict boy; otherwise girl:

def naivebayes(x, pos_py, neg_py, posprob, negprob):
    log_pos = np.log(pos_py) + x @ np.log(posprob)
    log_neg = np.log(neg_py) + x @ np.log(negprob)
    return log_pos - log_neg                 # log P(y=+1|x) / P(y=-1|x)

def classify(x, *params):
    return np.sign(naivebayes(x, *params))
Shortcut: because the log-odds is linear in x, the whole model collapses to a weight vector w = log(posprob) − log(negprob) and bias b = log(pos_py) − log(neg_py). Prediction is just sign(w · x + b).
